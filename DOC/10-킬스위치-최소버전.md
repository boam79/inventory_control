# 10 — 킬스위치·최소 버전

**도입 버전:** `1.0.49` (이 버전부터 원격 정책을 읽음)  
**정책 파일:** [`policy/kill-switch.json`](../policy/kill-switch.json) (GitHub `main` 브랜치)  
**공개 URL:** https://raw.githubusercontent.com/boam79/inventory_control/main/policy/kill-switch.json

---

## 대화·결정 요약

| 결정 | 내용 |
|------|------|
| 목적 | 무단 배포·사용 시 **개발자가 원격으로 실행을 막을 수 있음** |
| 서버 | **별도 서버·관리 UI 없음** — GitHub 저장소 파일만 사용 |
| 의원 UI | **설정 화면에 토글 없음** (개발자만 저장소에서 조작) |
| minVersion 기준 | **킬스위치를 읽을 수 있는 첫 릴리스** = `1.0.49` |
| 강제 업데이트 | 기존 Velopack 강제 업데이트 **유지**. 순서: **강제 업데이트 → 정책(킬·minVersion)** |
| 오프라인 | 정책 fetch 실패 시 **허용(fail-open)**. 의원 업무 우선, 실패는 로그 |
| 누가 스위치 | **개발자만** (`kill` / `minVersion` 편집) |

### 「킬 전용 빌드를 배포한다」와의 차이

| 방식 | 설명 |
|------|------|
| 킬 전용 빌드 배포 | 새 설치본을 만들어 배포해야 하며, 이미 돌고 있는 구버전은 자동으로 안 멈춤 |
| 원격 킬스위치 (본 기능) | `main`의 JSON만 바꾸면, **정책을 읽는 클라이언트(1.0.49+)** 가 다음 실행 시 즉시 차단 |

구버전(1.0.48 이하)은 정책 파일을 읽지 않으므로, 그 클라이언트는 **강제 업데이트로 1.0.49+로 올린 뒤** 정책이 적용됩니다. `minVersion`을 `1.0.49`로 두면, 정책을 읽을 수 있는 클라이언트 중 그보다 낮은 버전도 차단됩니다.

---

## 시나리오 (무단 확산)

1. 설치본이 허가되지 않은 PC에 퍼진 경우
2. 개발자가 GitHub에서 `policy/kill-switch.json`의 `"kill": true`로 저장
3. **1.0.49 이상** 앱이 시작되면 강제 업데이트 확인 후 정책을 읽고, 차단 메시지(취소 없음) → **앱 종료**
4. 다시 허용하려면 `"kill": false`로 되돌림 (새 릴리스 불필요)

## 개발자 조작법

### 파일 위치

저장소: `policy/kill-switch.json`  
GitHub에서 편집: https://github.com/boam79/inventory_control/blob/main/policy/kill-switch.json  
→ **Edit** → 저장(Commit to `main`). **새 Release를 만들 필요 없음.**

### 스키마

```json
{
  "kill": false,
  "minVersion": "1.0.49",
  "message": "사용이 중지되었습니다. 개발자에게 문의하세요.",
  "minVersionMessage": "구버전은 사용할 수 없습니다. 프로그램을 다시 실행해 업데이트를 완료하세요."
}
```

| 필드 | 의미 |
|------|------|
| `kill` | `true`면 사용 중지(차단 후 종료). `false`면 킬 비활성 |
| `minVersion` | 이 버전 **미만**이면 차단. 기본·권장: 킬스위치 도입 버전 `1.0.49` |
| `message` | kill 시 표시 문구 |
| `minVersionMessage` | 최소 버전 미달 시 표시 문구 |

### 킬 ON / OFF

- **중지:** `"kill": true` → `main`에 커밋
- **재개:** `"kill": false` → `main`에 커밋

몇 초~수 분 내 raw URL에 반영됩니다. 이미 실행 중인 앱은 **다음 시작**에 적용됩니다.

### minVersion 올리기

예: 보안 패치 `1.0.55` 이후만 허용하려면:

```json
"minVersion": "1.0.55"
```

그 전에 **해당 버전을 Release로 배포**하고, 강제 업데이트가 `1.0.55`로 올리게 한 뒤 `minVersion`을 올리는 것이 안전합니다. (그렇지 않으면 아직 업데이트 못 한 1.0.49~1.0.54도 차단될 수 있음)

## 앱 동작 순서 (시작 시)

1. **강제 업데이트** (Velopack): 새 릴리스가 있으면 취소 불가 적용·재시작  
   - 오프라인·확인 실패 → 업무 허용 (기존과 동일)
2. **원격 정책** (`kill-switch.json`):
   - `kill == true` → 차단 대화상자 → 종료
   - 로컬 버전 &lt; `minVersion` → 차단 대화상자 → 종료
   - fetch/파싱 실패 → **허용(fail-open)** + 경고 로그

설정·환경설정 화면에는 이 기능을 **표시하지 않습니다.**

---

## 강제 업데이트의 역할

- 1.0.48 이하는 정책 파일을 모름 → **강제 업데이트로 1.0.49+ 설치**가 전제
- 1.0.49+는 정책으로 킬·최소 버전을 강제할 수 있음
- 둘 다 오프라인 시에는 **업무를 막지 않음** (클리닉 우선)

---

## 오프라인

| 상황 | 동작 |
|------|------|
| 정책 URL 접속 실패 | 앱 **사용 가능**, 로그만 남김 |
| JSON 깨짐·필수 필드 없음 | 동일 (fail-open) |
| 정책 수신 + kill/min 위반 | **차단 후 종료** |
