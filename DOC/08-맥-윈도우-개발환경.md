# 08 — Mac·Windows 개발 환경

**문서 기준일:** 2026-08-22  
**관련 커밋:** `cb4aaf8`  
**대상:** 개발자

같은 git 저장소를 **Windows와 macOS에서 함께** 씁니다. 의원에 설치되는 프로그램은 그대로 Windows WPF입니다. Mac에서는 화면을 띄우지 않고, 재고 규칙·DB·테스트만 개발합니다.

---

## 한 줄 요약

| 구분 | Windows | macOS |
|------|---------|-------|
| 도메인 로직 (`Inventory.Core`, `Inventory.Infrastructure`) | 가능 | 가능 |
| 단위 테스트 (`Inventory.Tests`) | 가능 | 가능 |
| 솔루션 로드·빌드 | WPF 앱 포함 | App은 UI 없는 스텁으로 빌드 |
| 화면 (`dotnet run --project Inventory.App`) | 가능 | **불가** |
| Setup.exe (`scripts/pack-installer.ps1`) | 가능 | **불가** |
| 의원 PC와 같은 UX 확인 | 가능 | **불가** (Windows 필요) |

WPF를 Avalonia 등으로 옮기지 않습니다. UI 확인과 설치본 검증은 항상 Windows에서 합니다.

---

## 매일 쓰는 명령

양쪽 공통:

```text
dotnet test
```

한 번에 복원·빌드·테스트:

```powershell
# Windows
powershell -File scripts/dev.ps1
```

```bash
# macOS
./scripts/dev.sh
```

`scripts/dev-mac.sh`는 `dev.sh`를 부르는 별칭입니다.

Windows에서만:

```powershell
dotnet run --project Inventory.App
powershell -ExecutionPolicy Bypass -File scripts/pack-installer.ps1
```

CI: 푸시와 PR마다 GitHub Actions가 **windows-latest**와 **macos-latest**에서 테스트를 돌립니다.  
https://github.com/boam79/inventory_control/actions

## Windows 개발 PC

1. [.NET 10 SDK](https://aka.ms/dotnet/download) 설치
2. 저장소 클론 후 `powershell -File scripts/dev.ps1`
3. 화면: `dotnet run --project Inventory.App`
4. 설치본이 필요할 때만 `vpk`(`.config/dotnet-tools.json`)와 `scripts/pack-installer.ps1`

SDK 버전은 저장소 루트 `global.json`이 10.0.x로 맞춥니다 (`rollForward: latestFeature`).

배포 절차는 [06-업데이트-배포.md](./06-업데이트-배포.md)를 따릅니다.

## macOS 개발 PC

### 1. SDK 설치 (PC당 최초 1회)

Homebrew `dotnet-sdk` cask는 관리자 암호(sudo)가 필요해 이 환경에서는 쓰지 않습니다. 사용자 폴더에 설치합니다.

```bash
curl -sSL https://dot.net/v1/dotnet-install.sh | bash /dev/stdin --channel 10.0 --install-dir "$HOME/.dotnet"
```

### 2. PATH

`~/.zshrc`에 넣거나, 작업 전에 `scripts/mac-env.sh`를 source 합니다.

```bash
export DOTNET_ROOT="$HOME/.dotnet"
export PATH="$DOTNET_ROOT:$DOTNET_ROOT/tools:$PATH"
```

확인:

```bash
dotnet --version
```

`10.0.x`가 나오면 됩니다.

Cursor를 Dock/런처에서 연 경우에는 PATH를 못 읽을 수 있습니다. **Cursor를 한 번 종료했다가 다시 실행**하세요.

### 3. 테스트

```bash
./scripts/dev.sh
```

`dotnet run --project Inventory.App`은 Mac에서 화면이 뜨지 않는 것이 정상입니다.

## 솔루션이 OS마다 다르게 빌드되는 이유

| 프로젝트 | 대상 프레임워크 | 역할 |
|----------|-----------------|------|
| `Inventory.Core` | `net10.0` | 제품명, 역할, DB 경로. 양쪽 동일 |
| `Inventory.Infrastructure` | `net10.0` | SQLite, 재고, Excel, 백업, 예측. 양쪽 동일 |
| `Inventory.Tests` | `net10.0` | xUnit. **App 프로젝트를 참조하지 않음** |
| `Inventory.App` | Windows: `net10.0-windows` + WPF / 그 외: `net10.0` 라이브러리 스텁 | 화면은 Windows만 |

`Inventory.App.csproj`가 OS를 나눕니다.

- **Windows:** `UseWPF`, LiveCharts WPF, Velopack. 기존 데스크톱 앱.
- **macOS/Linux:** WPF 소스·패키지를 넣지 않고 `MacDevPlaceholder.cs`만 컴파일합니다. 솔루션이 깨지지 않게 하기 위한 빈 라이브러리입니다.

그래서 Mac에서 `dotnet build`는 성공해도, 의원용 UI는 생기지 않습니다.

## 스크립트·설정 파일

| 파일 | 용도 |
|------|------|
| `scripts/dev.sh` | macOS/Linux 복원·빌드·테스트 |
| `scripts/dev.ps1` | Windows(또는 PowerShell 7) 복원·빌드·테스트 |
| `scripts/dev-mac.sh` | `dev.sh` 래퍼 |
| `scripts/mac-env.sh` | `DOTNET_ROOT`·PATH |
| `scripts/pack-installer.ps1` | Setup.exe (Windows만) |
| `global.json` | SDK 10.0.x |
| `.github/workflows/ci.yml` | Windows + macOS 테스트 |
| `.gitattributes` | 셸 스크립트 LF 유지 |

내부 작업 메모(`.cursor/scratchpad.md`)는 git에 넣지 않습니다.

## 로컬 데이터 경로

앱이 쓰는 기본 폴더 이름은 `SpringClinicInventory`입니다. `Environment.SpecialFolder.LocalApplicationData` 아래입니다.

| 항목 | Windows | macOS (개발 중 테스트가 기본 경로를 쓸 때) |
|------|---------|------------------------------------------|
| DB | `%LOCALAPPDATA%\SpringClinicInventory\inventory.db` | `~/Library/Application Support/SpringClinicInventory/inventory.db` |
| 로그 | `%LOCALAPPDATA%\SpringClinicInventory\logs\` | 같은 폴더 아래 `logs/` |
| 백업 | `%LOCALAPPDATA%\SpringClinicInventory\backups\` | 같은 폴더 아래 `backups/` |

의원 운영 DB는 Windows 설치본의 AppData에만 있습니다. Mac 경로의 파일은 개발용입니다. 운영 데이터를 Mac으로 복사해 덮어쓰지 마세요.

---

## 하면 안 되는 것

- Mac에서 WPF 화면이 뜨기를 기대하지 말 것
- Mac에서 `win-x64` WPF publish / Setup.exe를 만들지 말 것 (Windows 타기팅 팩·Velopack 설치본은 Windows 툴체인)
- Homebrew `dotnet-sdk` cask로 SDK를 설치하려다 sudo 암호에 막히면, 위의 `dotnet-install.sh`를 쓸 것
- 기능 검증을 localhost 웹으로 대체하지 말 것. 이 제품은 데스크톱 앱이다. UX는 Windows 개발 실행 또는 의원 설치본에서 확인한다.
