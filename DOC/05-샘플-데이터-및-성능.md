# 05 — 샘플 데이터 및 성능

## 샘플(테스트) 데이터 개요

대시보드·통계·예측 기능을 **데모·검증**할 때 사용하는 가짜 데이터입니다. **실제 의원 운영 DB를 조용히 덮어쓰지 않도록** 여러 안전장치가 있습니다.

### 기본 규모 (v1.0.20~)

| 항목 | 값 |
|------|-----|
| 품목 수 | **1,000개** (정확히) |
| 거래 기간 | 직전 12~13개월 |
| 계절성 | 봄·여름·가을·겨울별 사용량 배율 상이 |
| LOT | 일부 품목만 (최대 300개 품목) |
| 재고 | 0 미만 불가 |

---

## 자동 시드 (앱 시작 시)

**조건:** DB에 입고·출고·조정 **거래가 0건**일 때만 자동 실행

- 품목 1,000개 + 1년치 계절 거래 생성
- **이미 거래가 1건이라도 있으면** 자동 시드 **하지 않음**

> v1.0.1에서 이미 거래를 넣은 DB는 자동 시드가 돌지 않습니다.

---

## 수동 시드·다시 만들기

### 환경설정 > 개발자 (관리자)

- **테스트 데이터 다시 만들기** → `DemoSeedService.ReplaceSample`
- 확인 후 **기존 품목·입고·출고를 모두 삭제**하고 요청 개수(기본 1,000)로 **교체**
- 예: 10,000개 품목 DB → 1,000개로 **줄이기** 가능 (v1.0.21 수정)

### CLI (개발 PC)

```powershell
dotnet run --project Inventory.App -- --seed-demo
dotnet run --project Inventory.App -- --seed-demo --force
```

- `--force`: 기존 데이터 삭제 후 재생성

---

## ReplaceSample vs 기존 Seed

| 함수 | 동작 |
|------|------|
| `SeedDemo` / 자동 시드 | 빈 DB에만 추가 |
| `ReplaceSample` | **전체 삭제 후** 정확한 개수로 재생성 |

v1.0.21 이전에는 「다시 만들기」 시 기존 품목이 남는 버그가 있었고, **ReplaceSample**로 수정되었습니다.

## 성능 최적화 (v1.0.20)

**목표:** 품목·거래가 늘어나도 **통계·대시보드**가 느려지지 않게

| 영역 | 내용 |
|------|------|
| `DashboardMetrics` | 월별 출고·KPI 집계 쿼리 개선 |
| `TrailingMonthlyIssuesByItems` | 여러 품목 한 번에 조회 (N+1 완화) |
| `ReportAnalytics` | 보고서 필터·집계 |
| 테스트 | `QuerySpeedTests` — 소스에 비효율 패턴 없는지 검사 |

### 확인 방법

```powershell
dotnet test --filter QuerySpeed
dotnet test --filter DemoSeed
```

대량 샘플(1,000품목, 수만 건 거래)로 대시보드·통계 화면 전환 시간을 육안 확인합니다.

## Excel과 샘플의 관계

- Excel **가져오기**는 백업 화면에서만 (운영 데이터 이관용)
- 샘플 데이터는 **코드 생성** (`DemoSeedService`) — Excel과 별개
- 빈 수식 행은 거래로 처리하지 않음
- 마스터+기초+이력 동시 가져올 때 **이중계산 경고** 후 기초 건너뜀

---

## DB 초기화 (완전히 새로 시작)

1. 앱 종료
2. `%LOCALAPPDATA%\SpringClinicInventory\inventory.db` **백업 후 삭제**
3. 앱 재실행 → 빈 DB + (거래 0건이면) 자동 시드

또는 환경설정에서 **ReplaceSample** (관리자, 확인 필요).
